# Limites G4

Configuration interne dans `dgloss/config.py`, sans nouveaux contrôles dans
la boîte de dialogue :

- `budget_seconds = 20.0` : budget initial hors G4 ;
- `g4_max_passes = 2` : deux passes G4 supplémentaires au maximum, donc
  trois passes totales en comptant la première passe ; zéro désactive les
  passes supplémentaires ;
- `g4_min_gain_percent = 10.0` : dès la troisième passe totale, arrêt si son
  gain de longueur est inférieur ou égal à 10 % du gain de la précédente.

Le rapport utilise les gains incrémentaux non arrondis, et non la longueur
restante de la carte. Si le gain précédent est nul, le rapport ne déclenche
pas l'arrêt. L'absence de transformation arrête toujours G4. La limite du
nombre de passes reste applicable dans tous les cas.

G4 fonctionne même si le budget initial est épuisé. Ses passes n'ont pas de
limite temporelle ; le temps total peut donc dépasser 20 secondes. La case
G4 existante reste disponible, et l'autogloss local reste indépendant.

Validation : 53 tests ciblés réussis (dialogue, G4, autogloss, transaction
Centering). La suite G0/G1/G3 et G4 élargie donne 72 succès, un test de
dépendances exclu car le lanceur précharge explicitement le plugin, et un
échec Centering également reproduit avec le pipeline de HEAD avant ce
correctif (`test_a_later_gloss_completely_removes_a_longer_centering_path`).
Les nouveaux cas couvrent le seuil exact, une valeur juste supérieure,
un seuil configuré différent, un gain précédent nul, zéro passe, les valeurs
invalides et l'exécution réelle de G4 après épuisement du budget initial.
